# 功能与验证清单

本文仅记录实际代码中的功能。HTML5 表单增强、基础 HTML、JavaScript、CSS 和可访问性分别归类；并非所有能力都是 HTML5 新特性。

## HTML5 表单增强

| 功能 | 代码所在文件 | 实现方式 | 验证方法 |
| --- | --- | --- | --- |
| 用户名约束 | register.html | `required`、`minlength="3"`、`maxlength="16"`、`pattern="[A-Za-z0-9_]{3,16}"` | 属性静态检查通过；待人工：输入 `ab`、中文、空格、`abc-123` 应失败，`abc`、16 位合法字符应通过，第 17 位通常被限制输入 |
| 邮箱约束 | 两个 HTML 文件 | `type="email"`、`required` | 属性静态检查通过；待人工：空值、`abc` 应失败，`student@example.com` 应通过格式检查 |
| 密码长度 | 两个 HTML 文件 | 密码字段保留 `minlength="8"`、`required` | 属性静态检查通过；待人工：逐个输入 7 位和 8 位密码，检查原生长度提示 |
| 协议及学科必选 | register.html | 复选框与 select 的 `required`，学科默认空值 | 待人工：其他字段合法，不勾协议或不选学科不能提交 |
| 自动填充提示 | 两个 HTML 文件 | 注册用户名 `username`、邮箱 `email`、密码 `new-password`；登录邮箱 `username`、密码 `current-password` | 已核对源码；待人工检查浏览器建议，实际效果取决于浏览器和密码管理器 |
| 原生约束验证 | 两个 HTML 文件、script.js | 未添加 `novalidate`；浏览器提交前验证，脚本调用 `reportValidity()` | 无 `novalidate` 静态检查通过；待人工：空表单及逐项非法值提交时显示浏览器提示，修正后再提交 |

## JavaScript

| 功能 | 代码所在文件 | 实现方式 | 验证方法 |
| --- | --- | --- | --- |
| 密码一致性 | script.js | 在 `input`、`change` 事件中调用 `setCustomValidity()`；匹配时设为空字符串 | 模拟逻辑检查通过；待人工：两次密码不同，修正确认密码后提交；再修改第一个密码造成不一致，改回后重新提交 |
| 显示/隐藏密码 | script.js、两个 HTML 文件 | 三个独立 `type="button"` 按钮切换对应 input 的 type，并更新文本及 ARIA 状态 | 按钮类型静态检查和切换模拟检查通过；待人工点击与键盘激活，确认不提交表单 |
| 演示提交 | script.js | `preventDefault()`、`reportValidity()`、中文成功提示；没有真实注册或登录 | 模拟检查通过；待人工：合法提交显示“前端演示成功，未连接服务器”，无页面跳转、无表单网络请求 |
| 密码清空 | script.js | 按 `data-password` 查找输入框，清空值并恢复 password 类型及按钮状态 | 模拟检查通过；待人工：先显示全部密码再成功提交，应全部清空并隐藏 |
| 旧提示清除 | script.js | 再次编辑表单时清空状态文本 | 模拟检查通过；待人工：成功后编辑字段，成功提示应消失 |

## 可访问性

| 功能 | 代码所在文件 | 实现方式 | 验证方法 |
| --- | --- | --- | --- |
| 标签与格式说明 | 两个 HTML 文件 | 输入框和下拉框使用 for/id 标签；单选、复选框采用包裹式 label；说明通过 `aria-describedby` 关联 | ID 唯一性及引用目标检查通过；待人工点击标签并用读屏软件核对控件名称和说明 |
| 键盘操作与焦点 | style.css、两个 HTML 文件 | 原生交互控件按文档顺序聚焦，无正数 tabindex；深蓝 `:focus-visible` 焦点环、身份选项 `:focus-within` | 待人工 Tab/Shift+Tab 遍历表单、显隐按钮、协议、提交及跳转链接；单选组使用方向键、复选框使用空格；确认无焦点陷阱 |
| 显隐状态表达 | 两个 HTML 文件、script.js | `aria-controls`、动态 `aria-label` 和 `aria-pressed` | 属性引用和状态更新模拟检查通过；待人工读屏检查按钮名称与状态 |
| 提交状态播报 | 两个 HTML 文件、script.js、style.css | 持续存在的空状态区域使用 `role="status"`、`aria-live="polite"`、`aria-atomic="true"`；仅更新文本，空状态不占视觉空间 | 属性静态检查通过；待人工使用读屏软件提交，确认中文结果得到播报 |
| 装饰隐藏与缩放 | 两个 HTML 文件、style.css | 纯装饰区域 `aria-hidden="true"`；viewport 不限制缩放 | 待人工读屏确认不重复读装饰；200% 缩放检查内容及控件未被遮挡 |

## 本轮检查记录与边界

- 已执行并通过：`node --check script.js`。
- 已执行并通过：Node 静态检查，包括相对引用存在、ID 唯一、标签与 ARIA 引用目标存在、表单约束属性、显隐按钮类型、viewport、媒体查询存在、无外部资源引用。
- 已执行并通过：Node VM 模拟表单检查，包括密码不一致拦截、从两个密码框修正错误、显隐切换、阻止默认提交、清空明文状态密码和恢复按钮、清除旧成功提示。
- 这些检查使用临时命令执行，没有向项目加入测试依赖。模拟表单不包含浏览器真实的原生验证、布局、焦点或读屏实现，不能据此宣称浏览器测试已通过。
- 表中所有“待人工”项目尚未执行；特别是无横向溢出、跨浏览器表现、自动填充、键盘全流程和读屏播报需要实际浏览器验收。
